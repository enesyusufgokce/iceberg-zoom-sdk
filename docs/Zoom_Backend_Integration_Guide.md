**ICEBERG · ZOOM SDK DEEP DIVE**

**Backend Integration Guide: PHP / Laravel & Go**

_How to generate Zoom SDK credentials, call the Zoom API, and handle webhooks from Lifesycle's backend_

# **Purpose & Scope**

This guide translates the Zoom SDK authentication model (Meeting SDK JWT, ZAK, OBF, OAuth) into concrete backend architecture for two stacks: PHP/Laravel and Go. It assumes the reader already understands what each token represents — see the Authentication Deep Dive for that background. This document focuses on where each token is generated, which endpoints call it, how credentials are stored, and how the two stacks fit together.

**Golden rule**

Every credential that can mint a token (Client Secret, SDK Secret, Webhook Secret Token) lives on the backend only. The frontend only ever receives short-lived, already-signed tokens (JWT, ZAK, OBF) — never the secrets used to create them.

## **Quick Recap: Who Generates What**

| **Token**              | **Generated by**                 | **Needs**                                          |
| ---------------------- | -------------------------------- | -------------------------------------------------- |
| **SDK JWT**            | Your backend (Laravel or Go)     | Client ID + Client Secret, signed HMAC SHA256      |
| ---                    | ---                              | ---                                                |
| **OAuth access token** | Zoom, after user authorizes      | Client ID + Client Secret + authorization code     |
| ---                    | ---                              | ---                                                |
| **ZAK**                | Zoom API, called by your backend | A valid OAuth access token (user:read:zak scope)   |
| ---                    | ---                              | ---                                                |
| **OBF**                | Zoom API, called by your backend | A valid OAuth access token (user:read:token scope) |
| ---                    | ---                              | ---                                                |

# **PHP / Laravel Integration**

There is no official Zoom package for Laravel, and the community packages on Packagist vary widely in maintenance quality — several are abandoned, and none specifically cover Meeting SDK JWT generation with ZAK/OBF. The recommended approach mirrors Zoom's own official pattern (their sample auth-endpoint apps are simple Node/Express services): build a small, purpose-built service class rather than depending on a third-party wrapper. This keeps the security-critical signing logic auditable and avoids inheriting an abandoned dependency.

## **1\. Packages**

- firebase/php-jwt — the standard PHP JWT signing library, also used internally by several community Zoom packages.
- guzzlehttp/guzzle — for calling the Zoom REST API (ZAK, OBF, meeting creation). Laravel's own Http facade (built on Guzzle) works equally well and is preferred for new code.

```
composer require firebase/php-jwt
```

## **2\. Environment configuration**

Store all Zoom credentials in .env, never in source. Add a config/zoom.php that reads from env() so the rest of the app never touches getenv() directly.

```
# .env
ZOOM_SDK_CLIENT_ID=xxxxxxxxxxxxxxxx
ZOOM_SDK_CLIENT_SECRET=xxxxxxxxxxxxxxxx
ZOOM_OAUTH_CLIENT_ID=xxxxxxxxxxxxxxxx
ZOOM_OAUTH_CLIENT_SECRET=xxxxxxxxxxxxxxxx
ZOOM_OAUTH_REDIRECT_URI=https://lifesycle.app/zoom/oauth/callback
ZOOM_WEBHOOK_SECRET_TOKEN=xxxxxxxxxxxxxxxx
```

```
// config/zoom.php
return [
    'sdk_client_id'     => env('ZOOM_SDK_CLIENT_ID'),
    'sdk_client_secret' => env('ZOOM_SDK_CLIENT_SECRET'),
    'oauth_client_id'     => env('ZOOM_OAUTH_CLIENT_ID'),
    'oauth_client_secret' => env('ZOOM_OAUTH_CLIENT_SECRET'),
    'oauth_redirect_uri'  => env('ZOOM_OAUTH_REDIRECT_URI'),
    'webhook_secret' => env('ZOOM_WEBHOOK_SECRET_TOKEN'),

```

## **3\. Recommended architecture**

- app/Services/Zoom/ZoomJwtService.php — signs Meeting SDK JWTs.
- app/Services/Zoom/ZoomOAuthService.php — handles the OAuth authorization-code exchange and token storage/refresh.
- app/Services/Zoom/ZoomTokenService.php — calls the ZAK and OBF endpoints using a stored OAuth access token.
- app/Http/Controllers/Zoom/MeetingAuthController.php — the endpoint the frontend calls right before joining.
- app/Http/Controllers/Zoom/WebhookController.php — receives and verifies Zoom webhook events.
- A zoom_oauth_tokens table (user_id, access_token, refresh_token, expires_at) — access tokens are only valid one hour and must be refreshed, not regenerated from scratch each time.

Zoom signs every webhook with an HMAC SHA256 signature. Verify it before trusting the payload, and always use a timing-safe comparison (hash_equals) rather than == or ===.

**OAuth token storage and refresh**

Access tokens expire in one hour. Store the refresh token and re-request an access token when expired, rather than re-triggering the OAuth consent screen. A Laravel scheduled job (or middleware check on read) works well here.

**Error handling checklist**

- Wrap every Zoom HTTP call in ->throw() (Laravel HTTP client) or try/catch, and log the response body — Zoom's error messages are usually specific enough to diagnose (invalid scope, expired token, invalid signature).
- Treat a 124 error code (invalid token) on ZAK/OBF calls as "needs re-authorization", not a transient failure — prompt the user to reconnect their Zoom account rather than retrying.
- Webhook handler must return a 2xx response within a few seconds regardless of downstream processing outcome — dispatch a queued job for anything non-trivial.

# **Go Integration**

Go has no Zoom-specific SDK either — the ecosystem here is entirely "call the REST API with a standard HTTP client and a general-purpose JWT library." This is intentional: Zoom's own philosophy is that these are plain JWTs and plain REST calls, so any language's standard tooling is sufficient.

## **1\. Libraries**

- github.com/golang-jwt/jwt/v5 — the maintained successor to the archived dgrijalva/jwt-go; the de facto standard for Go JWT handling.
- net/http (standard library) — sufficient for Zoom's REST API; no need for a heavier HTTP client library for this use case.

```
go get github.com/golang-jwt/jwt/v5
```

## **2\. When does a Go service make sense here?**

Laravel alone is enough for most of the Zoom integration surface. A separate Go service is worth the added operational complexity only when at least one of these is true:

- Webhook volume is high enough that a lightweight, low-latency handler measurably reduces load on the main Laravel app (Go's HTTP throughput per instance is materially higher).
- A long-running or streaming workload is involved — e.g. consuming Zoom's RTMS (Real-Time Media Streams) or processing recording/transcript webhooks continuously, which suits Go's concurrency model better than PHP-FPM's request-response cycle.
- The team wants a single internal Zoom gateway service reused by multiple products beyond Lifesycle (not just Laravel) — a Go binary is easy to deploy as a standalone microservice with a small footprint.

**Recommendation for this mission**

Build the Laravel implementation first — it covers the full Meeting SDK / Video SDK auth flow end to end and is sufficient for Lifesycle's near-term needs. Treat the Go service as an optional POC (POC 4) that demonstrates the pattern for a future high-throughput webhook or RTMS use case, not as a replacement for the Laravel backend.

## **3\. Recommended architecture**

- cmd/zoomgateway/main.go — entrypoint, HTTP server setup.
- internal/zoomauth/jwt.go — SDK JWT signing.
- internal/zoomauth/oauth.go — OAuth token exchange/refresh.
- internal/zoomauth/tokens.go — ZAK / OBF retrieval.
- internal/webhook/handler.go — webhook signature verification and event dispatch.
- If this service is meant to serve Laravel (rather than replace it), expose a small internal API — e.g. POST /internal/meeting-signature — authenticated with a shared internal service token, not exposed publicly.

hmac.Equal performs a constant-time comparison, which matters here — a naive == comparison leaks timing information an attacker could use to forge a valid signature byte by byte.

# **Security Checklist (Both Stacks)**

- Client Secret, SDK Secret, and Webhook Secret Token are backend-only — never sent to the frontend, never logged, never committed to version control.
- Generate SDK JWTs per-request, not once and cached — short expiry limits the damage if a token is intercepted.
- Fetch ZAK/OBF tokens immediately before use rather than caching them for later — both are meant to be short-lived.
- Verify webhook signatures with a constant-time comparison (hash_equals in PHP, hmac.Equal in Go) — never a plain string equality check.
- Reject webhook requests with a stale x-zm-request-timestamp (Zoom recommends a 5-minute tolerance window) to prevent replay attacks.
- Store OAuth refresh tokens encrypted at rest; treat them with the same sensitivity as the Client Secret since a leaked refresh token grants ongoing account access.
- Rotate the Webhook Secret Token and Client Secret if either is ever exposed (e.g. accidentally committed), and update Zoom Marketplace app settings immediately.
